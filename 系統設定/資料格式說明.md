# AI 代理資料格式說明

平台從 `AI代理資料.json` 讀取代理身分與協作流程。

| 欄位 | 用途 | 範例 |
|---|---|---|
| 名稱 | 代理顯示名稱與記憶識別 | 研究代理 |
| 圖示 | 畫布與對話圖示 | 🔎 |
| 角色 | 主要責任 | 資料研究與來源查證 |
| 人格 | 回應態度與判斷風格 | 嚴謹、重視證據 |
| 核心目標 | 代理長期不變的工作方向 | 提供可靠研究結果 |
| 專業 | 專業領域陣列 | 資料搜尋、來源評估 |
| 技能 | 可執行能力陣列 | 交叉比對來源 |
| 可用工具 | 網站實際提供或允許使用的工具 | Google 搜尋、知識庫讀取 |
| 知識文件 | 代理可以讀取的 Markdown 路徑 | 知識資料庫/常用資料.md |
| 模型 | 代理預設 Gemini 模型 | gemini-3.8-flash |
| 狀態 | 畫布目前狀態 | 工作中 |
| 任務 | 正在處理的工作 | 整理研究資料 |
| 完成進度 | 0 到 100 的整數 | 60 |
| 最後更新 | 最近執行時間 | 2026-09-14 13:00 |
| 位置 | 畫布預設座標 | `{"x":70,"y":230}` |

`連線` 表示畫布合作關係；`團隊流程` 決定「啟動全隊」的執行與交接順序。代理名稱必須與 `AI代理` 清單完全相同。

## AI 服務設定（多供應商）

`AI服務設定.json` 從 2026-09-14 起改為多供應商格式，`供應商` 是一個陣列，每個項目代表一家 AI 公司（目前是 Gemini、OpenAI、Claude）：

| 欄位 | 用途 | 範例 |
|---|---|---|
| 代碼 | 供應商識別碼，程式用來判斷要呼叫哪個 API | gemini |
| 名稱 | 顯示名稱 | Google Gemini |
| 金鑰標籤 | 該供應商金鑰輸入框的標籤文字 | Gemini API 金鑰 |
| 金鑰提示 | 輸入框的 placeholder | 貼上 AIza 開頭的金鑰 |
| 金鑰網址 | 申請金鑰的官方頁面 | https://aistudio.google.com/apikey |
| 現況 | 使用者目前的申請狀態，供平台顯示提醒 | 已有帳號，可直接使用 |
| 模型 | 該供應商可選的模型陣列，每個模型有代碼、名稱、輸入/輸出每百萬 token 價格（美元）與備註 | 見 JSON 內容 |

`AI代理資料.json` 裡每位代理的 `模型` 欄位只是「預設建議」，實際使用時使用者可以在 AI 工作台自由改選任何供應商、任何模型，對應 2026-09-14 訪談「依任務類型動態分派、使用者手動選模型」的決定。

## 共用錯誤記憶

`知識資料庫/已知問題與規則.md` 是所有代理共用的知識文件，記錄過去確認過的真實 bug 與教訓。每位代理的 `知識文件` 清單都包含這一份，執行任務前會先讀取，避免不同模型重複踩到同一個坑。檢查代理確認一個真實問題後，必須把它整理寫進這份文件（格式見文件內說明）。
